# User Experience and Recovery

[[Experience Principles]] governs this flow. Every primary action should let the user state an audible intention, hear a representative result quickly, compare it with the unchanged source at matched loudness where appropriate, and undo without losing the project.

## Primary journey

The default path is: choose local video/audio → review the recommended setup → enhance → preview the assembled result → download. The application handles local extraction, caching, representative preview generation, planning, and bounded chunk execution without asking the user to understand those implementation stages.

An optional **Adjust sound** disclosure exposes outcome-oriented global controls and representative preview comparison. **Quality and device details** exposes storage, memory, ETA, provider, and model information. **Mix and export details** exposes processed stems and export composition after enhancement. Blocking constraints, failures, material quality reductions, and required consent remain visible in the primary path.

Use stage-specific progress: download bytes; decode frames where observable; model completed/total chunks; export rendered/total frames; verification status. Show indeterminate progress when no trustworthy total exists. ETA is based on observed throughput and may change after provider fallback.

## Preview-first processing

Before committing a long full-timeline job, let the user choose or automatically propose short representative regions containing dialogue, music, ambience, and transients. Process those regions with the exact pinned artifact, provider, overlap, and settings intended for the full pass. Display the region boundaries, provider, processing settings, elapsed time, and a projected full-pass range derived from observed throughput.

Native Web Audio mix controls such as gain, mute/solo, width, EQ, clean dry/wet gains over already-rendered aligned material, and duck depth can be auditioned immediately. A control that changes ML inference, separation, enhancement, segmentation, or other offline DSP invalidates only the affected preview products first. The user commits the chosen settings to a sequential full pass after listening.

Dialogue Clean presents dependable denoising in outcome language. Experimental dereverberation is a separate opt-in preview, never silently folded into that dial. Its A/B is level-matched, its uncertainty is visible, and reverting preserves the prior denoised result.

A preview demonstrates the selected excerpts; it does not guarantee unpreviewed material. Make it easy to add a difficult region before commitment. After Enhance, expose the ordered technical plan with estimated chunk count/time/storage, but do not make the user approve fixed scheduler chunks. Completed audio becomes progressively auditionable using the original picture with replacement audio for video sources, or audio-only playback.

Use one global sound profile for a stable continuous recording. During initial and ongoing analysis, estimate acoustic-scene change points from sustained shifts in noise/source characteristics. Only a material, sufficiently confident change creates a visible region comparable to an autogenerated clip in a video editor. The user may audition that region and add a local override; uncertainty leaves the global profile unchanged. Region transitions include context/crossfades and remain independent of the model's fixed chunk boundaries.

The full pass uses identical pipeline versions and settings, bounded queues, overlap context, ordered chunk commits, and resumable checkpoints. If the provider changes, quality-reducing mode is proposed, or deterministic equivalence cannot be maintained, pause and request a new preview/commit rather than silently continuing.

The product says “saved locally”; implementation streams source media and PCM into OPFS and stores compact metadata in IndexedDB. It must never claim large media is stored in Web Storage/localStorage. During the import session, the original `File` may feed an object URL for video preview. The app must not call whole-file `arrayBuffer()` for admitted media. Browser-native video decoding still uses bounded internal decode/graphics buffers and may use hardware video surfaces; the contract prohibits a whole-file application allocation, not all RAM/VRAM use.

The mixer exposes accessible labels, units, numeric values, keyboard controls, visible focus, and recoverable defaults. Solo/mute state must remain clear without relying only on color. Waveforms use stored multi-resolution peaks; draw static waveform tiles separately from a requestAnimationFrame playhead overlay. Redraw only visible or invalidated tiles, and throttle accessible progress announcements.

## State and cancellation

Track `setup-required`, `ready`, `processing`, `paused`, `buffering`, `mix-ready`, `exporting`, and `recoverable-error` with a job ID and generation. Cancel at the earliest safe boundary, dispose workers/sessions where necessary, preserve the previous committed result, and remove only unreferenced temporary data. Explain if a non-interruptible inference call must finish before the operation stops.

Progress, errors, and model fallback notices must not erase the project. Persist checkpoint manifests after committed chunks; reopening resumes from a valid state or offers reprocessing when exact state cannot be restored.

Before entering any mode that reduces audio sample rate or otherwise trades quality for memory/throughput, show the reason, affected stage, resulting rate/quality, estimated resource benefit, and a cancel option. Record the choice in project processing metadata. Selecting FP16 model weights does not authorize a reduction in canonical PCM quality.

## Preflight quality planner

After source inspection and the local calibration probe, show only qualified processing/output profiles. Rank them from closest preservation of source fidelity to lower-resource alternatives. Each card states source audio/video handling, model and provider, processing rates, output format/bitrate, model download/installed bytes, persistent project bytes, peak temporary storage, estimated peak working memory, and an ETA range derived from measured local read/write throughput plus model warm-up/chunk throughput.

Disable a profile that does not fit the reserved memory or available persistent storage and name the bottleneck. Let the user choose another qualified profile, free local space, or cancel. Never lower sample rate, model quality, channel layout, or output fidelity automatically. Recalculate after provider fallback or a material throughput/storage change and require acknowledgement when the selected contract changes.

In MVP, “source-fidelity video” means the encoded picture track is passed through unchanged while enhanced audio is newly encoded/remuxed. The app does not reduce video resolution or transcode picture to save space. If a compatible audio encoder/container path is unavailable or a second video-sized output does not fit storage, the planner offers enhanced WAV without claiming a completed video file.

| Failure | User message/action | Recovery contract |
| --- | --- | --- |
| First visit offline | Connect once to download the app; a browser error may appear before any shell exists | No false offline-ready claim |
| Cached shell, missing model | Name missing package and required download | Allow available features; retry online |
| Interrupted/corrupt download | Retry affected package | Keep prior verified version; no partial activation |
| Unsupported/corrupt file | Identify codec/container or validation failure | Retain previous project; offer supported conversion guidance |
| Memory admission fails | File/device exceeds this configuration's processing limit | Offer validated shorter segment/lower-resource path |
| Storage quota/write failure | Show required/free estimate and local storage management | Pause before losing committed state; clean temporary files safely |
| GPU loss or unsupported operators | Explain fallback and likely slowdown | Recreate validated provider at a checkpoint, or stop cleanly |
| Playback underrun | Show buffering | Fade, refill all buses, resume aligned |
| Browser termination/storage eviction | Explain missing or incomplete local project | Validate manifests, recover committed chunks, or request original file |
| Export verification failure | Export did not pass safety/format checks | Keep project; rerender with safe gain or actionable error |

Project audio is private but locally stored. Provide an explicit project-delete action and separate temporary-data cleanup. Do not silently delete user projects to make room for models. A user-selected original file may need to be reselected after restart; persistent filesystem permission is not assumed.
